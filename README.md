# Disk Space Analyzer

Десктопное приложение для анализа использования дискового пространства. Сканирует выбранную папку, строит дерево директорий с размерами и группирует файлы по расширениям.

![Python](https://img.shields.io/badge/Python-3.10+-blue) ![PyQt6](https://img.shields.io/badge/PyQt6-6.0+-green) ![Platform](https://img.shields.io/badge/platform-Windows%20%7C%20Linux%20%7C%20macOS-lightgrey)

---

## Возможности

- Рекурсивное сканирование папки с отображением реального прогресса
- Дерево директорий с размерами, типами, владельцами и количеством файлов
- Сортировка по любому столбцу (числовая сортировка размеров работает корректно)
- Вкладка с группировкой файлов по расширениям и суммарным размером
- Сканирование в отдельном потоке — интерфейс не зависает
- Поддержка Windows и Unix (на Unix показывает реального владельца файла)

## Как пользоваться

1. Нажать кнопку **«Выбрать папку»**
2. Указать папку для анализа в диалоговом окне
3. Дождаться завершения сканирования (прогресс отображается в реальном времени)
4. Изучить результаты (ужаснуться от происходящего на диске):
   - Вкладка **«Структура каталогов»** — дерево с размерами, кликабельное и сортируемое
   - Вкладка **«Типы файлов»** — расширения, отсортированные по занимаемому месту

## Технические детали

**Почему итеративный обход вместо рекурсии**
`populate_tree_iterative()` использует явный стек (`list`) вместо рекурсивных вызовов. Это исключает `RecursionError` на глубоких деревьях (например, `node_modules` или архивы с вложенностью 500+).

**Как считается размер папки**
После обработки каждой директории размер её файлов «всплывает» вверх по дереву через словарь `nodes` (путь → узел). Каждый предок получает прибавку, пока не достигнут корень. Это позволяет за один проход `os.walk` получить корректный суммарный размер на всех уровнях.

**Почему два шага сканирования**
Сначала `count_items()` быстро считает количество элементов через `os.walk` без `os.stat` — это нужно для установки максимума прогресс-бара. Затем `get_tree()` делает полное сканирование с `os.stat` для каждого файла. Без первого шага прогресс-бар работал бы в режиме «неизвестно сколько осталось».

## Известные ограничения

- На **Windows** владелец файла не определяется (всегда отображается `"User"`) — WinAPI для этого требует отдельной библиотеки
- Символические ссылки **пропускаются** намеренно, чтобы избежать двойного счёта и зацикливания
- Файлы, недоступные из-за прав (`OSError`), молча игнорируются
- `main.py` использует устаревший импорт `from Base.kerl import ...` и не совместим с текущей структурой проекта
